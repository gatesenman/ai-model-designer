## RACI 矩阵跨格拖放：真正根因与策略

### 桌面复测结论

最终复测（Electron 刷新重开后）仍然失败：把「条目 1」从「任务 1 / 角色 A」拖到「任务 2 / 角色 B」的「+ 添加」中央，目标格只有反馈、不提交；反向拖同样不成功。截图见 `/workspace/qa-final-raci-reopen.webp`。

持久化本身是通过的：用属性面板把行列改成「任务 2 / 角色 B」，保存 `/workspace/qa-final-raci.amdproj` 并重开后保留；树项目重开后父级也保留。截图中条目已在「任务 2 / 角色 B」，来自属性面板修改而非拖放。

上一轮基于 HTML5 `dataTransfer` / 合成 `drop` 的修复和 jsdom 测试不能代表真实拖动成功。

### 根因

1. **HTML5 拖放在 Electron（尤其 Linux）上不稳定。** `dragover` 往往还能跑，于是格子会出现 `is-drop` 或「+ 添加」按钮 hover（虚线变蓝），看起来像“有反馈”。但原生 `<button>` 常常收不到 `drop`，或 `drop` 不冒泡；React 17+ 又把事件委托在根节点冒泡阶段。结果是反馈有了、`moveMatrixItem` 从未被调用。
2. **标签文本选中会抢走手势。** `.mx-item__label` 曾是 `cursor: text` 且没有 `user-select: none` / `-webkit-user-drag: none`。从文字上按下时，Chromium 更可能开始文本拖选，而不是我们绑定的 HTML5 条目拖动。`dragend` 仍可能触发并清掉内存 ref，进一步丢掉提交。
3. **`setDropHint` 引起的重渲染 + 只把监听绑在条目节点上并不稳健。** 源节点在重绘后可能丢失 pointer capture 或 HTML5 拖放会话。
4. **以 jsdom 手动 `dispatchEvent('drop')` 的测试会通过，即使真实 Electron 永远不派发 `drop`。** 这不能作为桌面验收依据。

### 现行策略（不再依赖 HTML5 dataTransfer）

条目移动改为 Pointer Events：

- `pointerdown` 记录条目 id、起点和 pointerId；`pointermove` / `pointerup` / `pointercancel` 挂在 `window` 上，会话放在 ref 里，避免重渲染打断。
- `pointerdown` 只记录会话并在 `window` 上监听 move/up；**越过拖动阈值后才 `setPointerCapture`**。若在按下时就捕获，Chromium 会把兼容鼠标事件（含 `dblclick`）派到条目容器而不是标签，双击改名会丢失。
- 移动超过 6px 才进入拖动，避免与单击选中、双击改名冲突；标记、删除、改名、输入框、添加按钮上的按下不会开始拖条目。
- 两次无拖动的 pointerup（500ms 内）也会进入编辑，不等待可能被吃掉的原生 `dblclick`；输入框在 click 完成后再挂载并聚焦。Esc 取消不写回，Enter / 失焦提交。
- 选中后条目上有显式「重命名」小按钮，F2 同样进入编辑；属性面板改名保留。
- 用 `elementFromPoint(clientX, clientY)` 再 `closest('.mx-cell')` 读取 `data-row` / `data-col`，落在「+ 添加」中央与落在格子空白处相同。
- 松开时若命中格子则 `getState()` + `moveMatrixItem` 写回并保持选中；未命中格子（越界）则取消。
- 拖动结束后在捕获阶段抑制残余 `click`，避免在「+ 添加」上松开时误新建条目。
- CSS：条目 `user-select: none`、`-webkit-user-drag: none`、`touch-action: none`；拖动期间画布禁止选中；幽灵预览 `pointer-events: none`，不挡住命中。

回归测试 `tests/matrix-canvas-dnd.test.tsx` 走 `pointerdown` / `pointermove` / `pointerup`，并用 `elementFromPoint` 命中「+ 添加」。包含：正向与反向提交、阈值内只选中、越界取消、从标记按钮起势不拖动、松开后残余 click 不新增、仅手动触发 HTML5 drop 不会移动，以及真实 pointerdown/up/click 双击序列的进入编辑、Esc 取消、Enter 提交、选中后的编辑按钮与 F2、改名入口不破坏跨格拖动。

## 1.1.0 关闭保护补丁（2026-11-22，Asia/Shanghai）

### 桌面首轮现象（不能当作窗口关闭已通过）

- 关于 / 页脚显示 1.1.0，新建与打开的未保存三按钮提示通过，取消能保留实体修改。这些是 **renderer** 路径。

- 帮助菜单当时只能看到「关于」，没有快捷键清单。

### 根因

**当时正在运行的主进程是旧版，不是“关闭保护已修好只需热更新”。** 证据：

- 工程内 `out/main/index.js` 修改时间为 2026-11-22 19:01（Asia/Shanghai），其中没有 `APP_CLOSE_REQUEST`、没有「键盘快捷键」菜单项。
- 关于/页脚 1.1.0 与新建/打开三按钮来自 renderer 热更新；原生菜单与窗口 `close` 事件只走 **main**。主进程未随 renderer 一起换成新代码时，关窗不会 `preventDefault`，应用直接退出并带走 dev 服务。
- 同时，即便换上当时的新 main，实现仍有缺口：只向 renderer 发关闭询问，没有 `before-quit` 处理，主进程不掌握 dirty，renderer 未就绪、崩溃或无应答时既可能卡住也可能在极端情况下失去确认。**因此不能盲判“代码已够用”。**

### 本次代码补强

- 主进程拦截窗口 `close` 与应用 `before-quit`。
- renderer 就绪/应答（ack）后走应用内三按钮确认，并先把草稿 flush 到本机会话。
- 3 秒内未 ack、renderer 未就绪、崩溃或关闭流程异常时，改用主进程原生「保存 / 不保存 / 取消」对话框，取消则继续编辑。
- dirty / filePath 随会话同步到主进程；编辑后约 400ms 写入草稿，不只靠长间隔自动保存。
- 「键盘快捷键」出现在 **帮助** 与 **视图**，加速键 F1；帮助菜单不使用 `role: help`。

### 根因（时序激活条无法打开右属性）

三处叠加，不是「保存丢了手动条」（重开后条体可见，模式为手动）：

1. **SVG 命中被关掉。** `.seq-svg` 设为 `pointer-events: none`，是为了让参与者头、消息标签等 HTML 叠层可点。激活条只画在 SVG 里，没有再打开命中，点击/双击条体都会穿透到舞台。
2. **点条体会清掉选择。** 舞台 `onClick` 在 `target === currentTarget` 时 `clearSelection()`。条体点不中时，事件落在 `.seq-stage` 上，选择被清空。
3. **App 不把激活条当选中。** `hasSelection` 只看 `selectedNodeId` / `selectedEdgeId` / `selectedNodeIds`。即便 `selectActivation` 成功，也不会自动打开右侧属性；标题仍显示「图级属性」。

右键回到项目概览：条体点不中时没有激活条菜单；返回概览仍是左上角项目名或返回按钮。本轮给条体加了右键选中并打开属性，不再把右键当空白点击处理。

### 修复

- 激活条组与加宽透明命中区（约左右各 8px）设 `pointer-events: auto`；点击/双击/右键都会 `stopPropagation` 并 `selectActivation`。
- `hasSelection` 包含 `selectedActivationId`，选中后自动打开属性并显示「激活条属性」。
- 工具栏下与图级属性中增加可发现的激活条列表，不依赖 SVG 命中即可选中、编辑参与者/起止、删除；删除可撤销。
