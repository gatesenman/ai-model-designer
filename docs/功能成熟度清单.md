## 1. 项目文件生命周期

### 现状证据（审计时）

- 工程文件为 `.amdproj` JSON；`coerceProject` 可兼容单模型 JSON。
- 先前 `save` 与 `save-as` 走同一条“另存为”对话框；自动保存调用 `markSaved()`，状态栏可能在尚未写入 `.amdproj` 时显示“已保存”。
- 主进程 `electron-store` 只存 `{ project }`，不记录文件路径，也无法区分“已保存到文件”与“仅有草稿”。
- 新建 / 打开 / 关闭窗口 / 退出缺少未保存三按钮确认。

### 缺陷与优先级

| ID | 级别 | 缺陷 |
|----|------|------|
| P0-01 | P0 | 保存与另存为行为相同，无法覆盖已打开文件 |
| P0-02 | P0 | 自动保存把草稿标成“已保存”，造成假成功 |
| P0-03 | P0 | 关闭窗口 / 新建 / 打开 / 关闭项目时可能丢未保存编辑 |
| P1-01 | P1 | 重启后恢复会话时，文件路径与 dirty 状态丢失或不诚实 |

### 实施结果

- 会话结构改为 `{ project, filePath, fileSaved }`，兼容旧草稿；`normalizeProjectSession` 负责归一。
- 已有路径且非“另存为”时走 `saveFileTo` 覆盖；否则弹对话框。
- 自动保存只写会话且 `fileSaved: false`，不再 `markSaved()`。状态栏区分「已保存」「未保存」「未保存到文件」。
- 新建 / 打开 / 关闭项目 / 窗口关闭：三按钮确认（保存 / 不保存 / 取消）；窗口 `close` 先 `preventDefault`，渲染进程确认后再 `destroy()`。
- `loadProject` 支持 `{ dirty, filePath }`；`newProject` 清空路径。

### 验收建议与剩余限制

- 建议桌面复测：打开已有 `.amdproj` 后编辑并 Ctrl+S 应覆盖原路径；另存为应换路径；未保存时关窗口出现三按钮；取消关闭应留下窗口；“不保存”后内容按选择丢弃。
- 本机 Windows 安装后的关闭路径仍未实测。自动保存间隔沿用设置，不是实时崩溃镜像。

## 4. AI 供应商配置与调用诚实性

### 现状证据

- 存在 mock 与多家 HTTP 供应商；主进程可超时。
- 状态栏曾直接显示供应商名，首页页脚曾写 “v2.0”，关于对话框可能让人以为真实 AI 已验证。
- 缺少密钥时仍可能发起调用或看起来“已配置就绪”。
- 无法取消进行中的请求；失败后没有明确重试入口。
- 设置中的 API Key 与普通设置一并明文/弱保护存储。

### 缺陷与优先级

| ID | 级别 | 缺陷 |
|----|------|------|
| P0-04 | P0 | 无密钥或离线模拟时，状态表达可能造成“已连上真实模型”的误解 |
| P1-05 | P1 | 调用失败后不能取消，也缺少重试入口 |
| P1-06 | P1 | API Key 与设置文件未分离，缺少安全存储优先策略 |
| P1-07 | P1 | 语言下拉禁用但未说明原因 |

### 实施结果

- `describeProviderStatus` 三分状态：`mock` / `ready` / `missing-key`。状态栏、AI 面板、设置页使用同一套文案；明确“不会假装已连通”。
- 缺密钥时生成/微调在渲染进程即拒绝，发送按钮禁用并给出原因。
- 每次调用带 `requestId`，主进程 `AbortController` 可取消；UI 有「取消」和「填回上一次指令以便重试」。
- API Key 优先 `safeStorage`，否则回退 electron-store 本地加密；设置 JSON 不再写入明文 Key。
- 语言选项注明“目前仅提供简体中文，该选项已禁用”。
- 关于框与首页版本改为 1.1.0，去掉易误导的 v2.0 表述。

### 验收与限制

- **真实供应商（OpenAI / Azure / DeepSeek / 自定义 / Ollama）在本环境无凭据、未做连通验收，不能当作已验证。** 仅保证：无密钥不会假成功；离线模拟会标明来源；失败与取消有反馈。
- `safeStorage` 在部分 Linux 环境可能不可用，此时走本地回退加密，不是云端托管保险。
